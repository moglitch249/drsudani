# نظام DrSudani - شحن جواهر فري فاير التلقائي (Razer Gold)

نظام متكامل ومؤتمت لشحن مجوهرات فري فاير (Free Fire) عبر حسابات Razer Gold باستخدام بوتات تعتمد على (Playwright) ولوحة تحكم مركزية (PHP/MySQL) لإدارة الطلبات وتوجيهها بشكل آمن وسريع. تم بناء النظام مع مراعاة أقصى درجات الحماية وتشفير البيانات.

## 🌟 المميزات (Features)
- **إدارة متعددة للبوتات (Multi-Bot Support):** يمكن تشغيل عدة بوتات في نفس الوقت موزعة على عدة خوادم (VPS).
- **توجيه ذكي للطلبات (Smart Routing):** منع تكرار الشحن (Double-charging) عبر نظام قفل الطلبات (Atomic Locks) و(Idempotency Keys).
- **مزامنة حية (Real-time Sync):** البوتات ترسل نبضات (Heartbeats) بانتظام لتحديث حالتها ورصيدها في لوحة التحكم.
- **إدارة الرصيد الذكية (Balance Management):** اكتشاف تلقائي لحالة الرصيد (منخفض/غير كافٍ).
- **مراجعة يدوية للطلبات (Manual Review):** عند حدوث أخطاء غير متوقعة (مثل الكابتشا أو فشل تأكيد الشحن)، يتم تحويل الطلب للمراجعة اليدوية بدلاً من الفشل لتجنب خسارة الأموال.
- **تخطي حماية ريزر:** إعدادات متقدمة للمتصفح لتجاوز كشف البوتات باستخدام Playwright مع بصمات متصفح مخصصة.

## 🏗 الهيكلية المعمارية (Architecture)
ينقسم النظام إلى قسمين رئيسيين:
1. **لوحة التحكم المركزية (PHP/MySQL):**
   - واجهة رسومية متقدمة (Dashboard) لمراقبة البوتات والطلبات الحية.
   - واجهات برمجة تطبيقات (APIs) آمنة تستقبل وتوجه الأوامر للبوتات.
   - تتصل بمتجر WooCommerce عبر واجهة برمجة التطبيقات لجلب الطلبات وتحديث حالتها.
2. **عقد البوتات (Python Workers):**
   - سكريبتات Python تعمل في الخلفية تستخدم `playwright` للتحكم بمتصفح مخفي (Headless).
   - تقوم بتوليد رموز التحقق الثنائية (TOTP) تلقائياً لتسجيل الدخول إلى حسابات Razer.

## 🔒 الأمان والتشفير (Security & Encryption)
تم تطبيق عدة طبقات أمنية صارمة في هذا المشروع:
- **تشفير البيانات الحساسة (AES-256-CBC):** جميع بيانات الحسابات (الإيميلات، كلمات المرور، أسرار OTP) المشتركة بين البوت والسيرفر يتم تشفيرها أثناء النقل باستخدام `API_SECRET_TOKEN` كمفتاح تشفير (SHA-256 Hash).
- **التحقق من الهوية (Authentication & HMAC):** لا يمكن لأي طرف خارجي الوصول إلى مسارات الـ API (مثل `get_pending.php` أو `update_status.php`) دون إرسال `API_SECRET_TOKEN` الصحيح.
- **حماية قواعد البيانات (SQL Injection Protection):** استخدام أوامر محضّرة (Prepared Statements) في PDO مع إيقاف `EMULATE_PREPARES` لسد ثغرات الحقن تماماً.
- **حماية من الهجمات الغاشمة (Brute-Force Protection):** في واجهة تسجيل الدخول `index.php`، يتم حظر الـ IP/الجلسة لمدة 15 دقيقة بعد 5 محاولات فاشلة.
- **أمان مجلد الأدلة (Evidence Directory):** يتم حفظ لقطات الشاشة لحالات الفشل خارج المجلد العام (Public HTML) لمنع الوصول المباشر عبر المتصفح.

## 🛠 المتطلبات التقنية (Prerequisites)

2. **قاعدة البيانات:** MySQL 8.0+ أو MariaDB.
3. **لغات البرمجة:**

## ⚙️ التثبيت والتشغيل لأول مرة (Installation & Setup)

### 1. إعداد قاعدة البيانات
- قم بإنشاء قاعدة بيانات جديدة في MySQL (مثال: `drsudani_bot`).
- (في حالة وجود ملف SQL) قم باستيراده لإنشاء الجداول، أو ستقوم لوحة التحكم بإنشائها تلقائياً (كما هو مبرمج في بعض الأجزاء).

### 2. إعداد السيرفر ولوحة التحكم (PHP)
- ارفع محتويات المجلد `php_system` إلى خادم الويب (في مجلد مثل `bot/` أو في الجذر `public_html/`).
- افتح الملف `php_system/config.php` واضبط الإعدادات التالية:
  ```php
  // بيانات قاعدة البيانات
  define('DB_HOST', 'localhost');
  define('DB_USER', 'root');
  define('DB_PASS', 'your_db_password');
  define('DB_NAME', 'drsudani_bot');

  // إعدادات WooCommerce لربط المتجر بالبوت
  define('WOO_STORE_URL', 'https://yourdomain.com'); 
  define('WOO_CONSUMER_KEY', 'ck_xxxxxxxxxxxxxxxxxxxxxxxx'); 
  define('WOO_CONSUMER_SECRET', 'cs_xxxxxxxxxxxxxxxxxxxxxxxx'); 

  // الرمز السري الحرج (يجب أن يكون معقداً وسرياً تماماً)
  define('API_SECRET_TOKEN', 'YOUR_COMPLEX_SECRET_TOKEN_HERE');
  
  // كلمة مرور دخول لوحة التحكم
  define('ADMIN_PASSWORD', 'your_secure_dashboard_password');
  ```
*ملاحظة: متغير `BOT_API_TOKEN` هو لتجهيزات مستقبلية ولا يؤثر على العمل الحالي في حال تغيير قيمته.*

### 3. إعداد خوادم البوتات (Python Workers)
- يمكنك تشغيل البوتات على نفس السيرفر أو على VPS منفصل (يُفضل VPS منفصل لتجنب استهلاك موارد الويب).
- قم بتثبيت بايثون وتثبيت المكتبات:
  ```bash
  pip install requests pyotp pycryptodome playwright
  playwright install chromium
  ```
- افتح ملف `freefire_bot.py` وعدّل المتغيرات في البداية:
  ```python
  API_BASE_URL = "https://your-domain.com/php_system/api" # رابط مجلد الـ API بالسيرفر
  API_SECRET_TOKEN = "YOUR_COMPLEX_SECRET_TOKEN_HERE" # يجب أن يكون متطابقاً تماماً مع السيرفر!
  ```

## 🚀 طريقة التشغيل اليومي (Workflow)

### أولاً: إضافة البوتات والحسابات
1. افتح متصفحك وادخل للوحة التحكم: `https://your-domain.com/php_system/index.php`.
2. أدخل كلمة المرور (`ADMIN_PASSWORD`).
3. من واجهة "الحسابات"، أضف حساب Razer Gold جديد:
   - الإيميل وكلمة المرور.
   - سر الـ 2FA (TOTP Secret) والذي يتيح للبوت توليد الأكواد سداسية الأرقام تلقائياً.
   - اربط هذا الحساب بمعرف بوت (مثال: `bot_node_1`).

### ثانياً: تشغيل البوت الفعلي (في بيئة البايثون)
افتح سطر الأوامر (Terminal) في المجلد الذي يحتوي على `freefire_bot.py`، وقم بتشغيل الأمر:
```bash
python freefire_bot.py bot_node_1 5000
```
- `bot_node_1`: هو معرف البوت الذي سيستخدمه لتعريف نفسه للوحة التحكم وسحب الحساب المرتبط به.
- `5000`: المنفذ (اختياري للنسخ الحالية، لكن يُستخدم كمعرف للـ worker).

**ماذا سيحدث عند التشغيل الأول؟**
1. سيقوم البوت بالاتصال بلوحة التحكم وجلب بيانات الدخول (مشفرة) وفك تشفيرها.
2. سيفتح متصفح مخفي (أو مرئي إذا قمت بتعديل الكود للمراقبة).
3. سيقوم بتسجيل الدخول لحساب ريزر جولد وحفظ جلسة المتصفح (Session) محلياً (لكي لا يضطر لتسجيل الدخول مع كل طلب، مما يقلل من احتمالية الحظر من ريزر).
4. في حالة وجود كابتشا أثناء تسجيل الدخول لأول مرة، قد يطلب منك البوت حلها يدوياً.

### ثالثاً: دورة حياة الطلب (Order Lifecycle)
1. عميل يطلب شحن جواهر من المتجر.
2. يتم تحويل الطلب إلى السيرفر وتصبح حالته `pending`.
3. البوت الحر (والذي يرسل نبضات حية Heartbeats) يسأل الـ API: هل هناك طلبات؟
4. السيرفر يسند الطلب له وتصبح الحالة `processing`.
5. البوت يفتح صفحة جارينا، يدخل معرف اللاعب (Player ID).
6. يختار باقة الشحن المطلوبة وينتقل للدفع عبر Razer Gold باستخدام رمز 2FA (TOTP) يتم توليده تلقائياً.
7. بعد نجاح الدفع، يبلغ البوت السيرفر بالنجاح، فتتغير حالة الطلب إلى `completed`، ويقوم السيرفر بإرسال أمر لمتجر WooCommerce لاكتمال الطلب.
8. في حال فشل أي خطوة (معرف لاعب خاطئ، رصيد غير كافٍ)، يتم رفع صورة الإثبات للوحة التحكم وتغيير الحالة لـ `failed` أو `manual_review`.

## 🛠 استكشاف الأخطاء وإصلاحها (Troubleshooting)

- **البوت لا يظهر كـ "متصل" في اللوحة:** تأكد من أن الـ `API_BASE_URL` صحيح، وأن `API_SECRET_TOKEN` متطابق في البايثون والـ PHP.
- **البوت يفشل دائماً في الدفع (رصيد غير كافٍ):** اللوحة ستقوم بتمييز البوت بلون تنبيهي (أحمر/أصفر). قم بشحن الحساب يدوياً واستأنف عمل البوت.
- **خطأ "Database Connection Failed":** راجع بيانات الاتصال بـ MySQL في ملف `config.php`.
